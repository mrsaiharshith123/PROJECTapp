# Internationalization (i18n)

CommitTrack supports **English** plus **22 scheduled languages of India**. Users pick a language in Profile → Language; the UI should show copy in that language only (no English fallback mixed in for wired screens).

**Brand:** CommitTrack by Daloy Tech — `brand.appName` stays **CommitTrack** in all locales; `brand.byDaloyTech` is translated.

## Layout

```
src/i18n/
├── languages.js          22 langs + en, RTL for Urdu
├── translate.js          loadMessages(), translate(), cache
├── I18nProvider.jsx      React context, useTranslation()
├── useCopy.js            Resolves COPY.* keys via t()
├── formatLocale.js       formatMonthYear() for month labels
├── engineLabels.js       Health / pressure label helpers
├── affordLabels.js       Affordability badges + warning keys
├── calcHelpKeys.js       Calculator help text keys (InfoTip)
├── messages/
│   ├── en.js             Source of truth (~1565 keys)
│   └── {locale}.js       One file per language code
└── __tests__/translate.test.js
```

App bootstrap wraps routes in `I18nProvider` (see `App.jsx`). Locale is stored in user settings and persisted via `migrateStorage.js`.

## Using translations in UI

```jsx
import { useTranslation } from "../../i18n";

function MyCard() {
  const { t, locale } = useTranslation();
  return (
    <>
      <h2>{t("home.title")}</h2>
      <p>{t("greeting.named", { name: userName })}</p>
    </>
  );
}
```

**Rules:**

1. Add new user-facing strings to `messages/en.js` first — never hard-code English in JSX for product copy.
2. Run `npm run sync:i18n` to copy missing keys into all locale files (English placeholder).
3. Translate locales with `npm run i18n:translate` (MyMemory) or `npm run i18n:translate:all` (Google fallback batch).
4. Use `{0}`, `{1}` placeholders — `translate()` replaces them in order.
5. Engine-generated English (insights, guidance registries) is **not** fully migrated yet — see [09-implementation-status.md](./09-implementation-status.md).

### COPY constants (legacy bridge)

Some screens still reference `constants/copy.js` paths. Prefer `t("key")` directly. Where `COPY.*` remains, use `useCopy()` from `src/i18n/useCopy.js`.

### Dates and engine labels

| Helper | Use for |
|--------|---------|
| `formatMonthYear(date, locale)` | Month hero, analytics headers |
| `translatePressureLabel(t, label)` | Pressure / burden labels |
| `translateAffordLabel(t, key)` | Expense simulator badges |

## Commands

| Command | Purpose |
|---------|---------|
| `npm run audit:i18n` | Key parity vs `en.js` + corruption scan |
| `npm run sync:i18n` | Add missing keys to all locale files |
| `npm run i18n:repair` | Fix corrupted placeholders / `tokens.push` artifacts |
| `npm run i18n:translate` | Fill empty/non-English keys via MyMemory API |
| `npm run i18n:translate:all` | Batch Google translate for all 22 locales (slow; dev only) |

**Typical flow after adding keys:**

```bash
# 1. Edit src/i18n/messages/en.js
npm run sync:i18n
npm run i18n:translate        # or translate:all for full refresh
npm run i18n:repair           # if batch translate glitched placeholders
npm run audit:i18n
npm run audit
```

## Audit

`npm run audit` includes:

- **Translations** — every locale file has the same keys as `en.js`
- **Copy tone** — formal language in user-facing strings (`npm run audit:copy`)

Strict mode fails on any i18n key mismatch or informal copy.

## Locale file conventions

- Each file starts with `/** Locale: {code} ({name}) */` when possible (helps duplicate-content checks).
- Keys are flat dot paths: `"home.hero.left": "Left"`.
- Do not edit locale files by hand for bulk translation — use scripts; hand-edit only for brand fixes or one-off corrections.

## Known gaps (June 2026)

Wired: Home month card, overview, financial pulse (partial), paycheck breakdown, commitments filters, profile hub + support/backup, navbar, expense simulator, money planner tabs, micro tips, admin dashboard (`admin.*`), admin profile tile (`profileHub.admin*`).

Admin strings are English product copy — synced to all locales via `sync:i18n` (same as other keys).

Still English or engine-only: Add/Edit bill forms, lending pages, onboarding, auth, analytics chart labels, goals/loan/chit/tax tool panels, guidance registries (`guidance/registry/*`), dynamic insight sentences from engines.

When wiring a screen, replace literals with `t("…")` keys and run `sync:i18n` in the same PR.
